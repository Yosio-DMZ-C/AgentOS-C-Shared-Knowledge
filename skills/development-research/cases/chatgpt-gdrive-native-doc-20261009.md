# 開発調査Skillの試行記録：ChatGPT → Google Drive（Googleドキュメント）

- 日付：2026-10-09（日本時間）
- ケース：I01 / 一般メモの保存・再読込（**一部の操作範囲のみPASS**）
- 利用手順：[開発調査・技術選定 Skill v0.1.0-preview](../SKILL.md)
- 対象：ChatGPTから接続済みGoogle Driveへの、架空メモの**Googleドキュメント形式**での作成・書込・再読込
- 公開範囲：個人の非公開ファイル本文、フォルダ・ファイルID、URL、トークン、アカウント情報は収録しない
- 判定：**限定PASS**。AgentOS-CのMarkdown階層・バイト完全性・別チャット継続利用は未検査

## 1. 選定の理由（簡易ADR）

- **目的**：最初の低リスクな1経路で、接続可否を調べ直す負担を減らし、必要な操作に絞った検査を実行する。
- **採用**：接続と個人KBの読込実績があったChatGPT → Google Driveを使用。外部のMake／Zapier、MCPサーバーや独自スクリプトは追加しない。
- **今回採用しない**：Notion、OneDrive、外部AIを使う構成。調査の範囲を1経路に限定するため。性能や安全性で不採用と判定したわけではない。
- **確認した操作**：既存フォルダのメタデータ取得、既存の入口ファイルの読取、**新しいテスト用Googleドキュメント**の作成・本文書込・再読込・削除。
- **未確認**：フォルダ内への新規Markdownファイル生成、既存の生Markdownの差分上書き、ID/履歴全体の保持、ファイルとしての完全エクスポートと復元、**新規チャットでの継続的な再読込**、長期運用、プランを変えた場合の操作。
- **再検証条件**：AIの接続権限・プラン変更、必要なファイル形式の変更、API/アプリ仕様更新、書込失敗、新規チャット利用が要件になったとき。

## 3. 工数の観測（推測と実測を区別）

- **Google Drive API/コネクタ操作は計8回**：フォルダ情報1、検索1、既存入口本文取得1、テスト文書の新規作成1、本文書込1、本文読込2、削除1。
- すでに連携実績のあるGoogle Driveだけを対象にし、他社製品の総当たり比較とAPIの新規実装はしなかった。
- **調査時間の短縮率は不明**。Skill未使用の条件を揃えた比較試験を行っていないため、「○%削減」「○分短縮」とは報告しない。
- 今回の有益な検出：Google Docsの段落テキストをそのままつなぐ実装では、改行の復元を忘れる可能性がある。KBの完全バックアップには段落/改行・原ファイルの形式やバイト保存を個別に検証する必要がある。

## 4. 再利用する接続制限カード（このケースだけの観測）

|項目|記録|
|---|---|
|client / destination|ChatGPT → 接続済みGoogle Drive|
|method|ChatGPTから使えるGoogle Driveの接続ツール（今回の接続）|
|verified_operations|既存ファイルの読取、**新規Googleドキュメントの作成・内容書込・段落再読込**、テストファイル削除|
|data_semantics|今回の単純な段落データの文字列・順序は保存。段落区切りの文字列再構成が必要|
|session_behavior|**新規チャットでは未確認**|
|evidence_level|**この利用者環境／今回のセッションで実動作**。他プラン・他アカウント・他AIへ一般化しない|
|limitations|Markdown生ファイル、AgentOS-C階層全体、完全エクスポート・復元、長期同期は未検証|
|fallback|完全性が必要で該当操作未検証なら元KBを維持し、検査済み完全版ZIP等の手動バックアップを使用|

## 5. 今後の最小課題

次に必要なのは全サービス比較ではなく、**この接続からAgentOS-Cの生Markdown 1ファイルを元の形式のまま保存・読戻しできるか**の独立テスト。成功するまでは「Google DriveとのGoogleドキュメント読書きが実行できた」とだけ報告し、「KB全体の直接同期が完全に保証された」と言わない。

## 6. 品質の境界

この試行は開発調査Skillの検証例であり、**正式Active公開のための独立レビュアー確認ではない**。既存の個人KBファイルには書込・削除していない。本人の非公開データや接続識別子は公開していない。
